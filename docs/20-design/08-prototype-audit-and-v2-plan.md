# 08 原型现状自审与 v2 规划

用户反馈"目前原型功能不全"。本文档是设计条线对 `prototype/index.html`（当前约 1020 行，单文件）的**功能自审**，并给出 v2 的信息架构、技术方案与实施顺序。**本轮不修改原型本身**，改原型是下一轮工作。

产品条线正在并行撰写 `docs/10-prd/07-design-coverage-and-gaps.md`（需求↔设计↔原型覆盖矩阵与缺口期望行为），截至本文档产出时尚未落地；下一轮应将该文档与本文档 §2/§3 交叉核对，避免结论冲突（见 §6 待产品确认问题 Q6）。

## 0. 方法与口径

- **方法**：逐行读取 `prototype/index.html` 的 DOM、CSS、内联 `<script>`，与 `02-user-flows.md`（9 条流程）、`03-screens/01–12.md`（12 个界面及其"状态"小节）、`05-collaboration-ux.md`（协同状态）、`06-extensibility-ux.md`（贡献槽位）逐条对照。
- **边界**：本文档不修改 `prototype/index.html` 或其他任何文件；不产出实现代码；v2 的路由/状态/组件以表格描述。
- **分类口径**（贯穿 §1）：
  | 分类 | 含义 |
  |---|---|
  | 可点击 | 操作后产生可观察的真实状态变化（DOM 属性、内容切换、视觉态迁移） |
  | 静态 | 有对应的可视元素，但未绑定事件，或绑定后无可观察变化——容易被误认为可交互 |
  | 仅提示 | 点击后只弹出一次性 toast/文案说明"演示"，不产生对应设计文档描述的真实状态 |
  | 不可达 | DOM/脚本已存在但没有任何 UI 入口可以触发（需打开控制台手动调用） |
- **覆盖口径**（贯穿 §2）：
  | 覆盖 | 含义 |
  |---|---|
  | 有 | 该状态/流程/槽位的关键路径与主要可点击交互均已实现，仅次要边界情况缺失 |
  | 部分 | 骨架或终态存在，但缺少中间态、真实数据联动，或只实现了定义中的一部分分支 |
  | 无 | 原型中不存在任何与之直接对应的可辨识元素（即使有相关的静态装饰也不算） |

## 4. 原型 v2 信息架构与技术方案

### 4.1 总体方案

- 继续保持**单文件、零外部资源**（无 CDN、无 build），可直接双击打开，也可作为 artifact 发布。
- 引入**极简 hash 路由**（无框架，监听 `hashchange`，按路由渲染对应 `<section>`，共享外壳常驻）：解决 G-24（深链接）与"12 个屏幕挤在一份线性 HTML 里导致状态组合爆炸"的根本问题。
- **共享外壳** + **每路由状态切换器**：状态切换器是对 v1 已有模式（"连接状态"下拉、`show-collab`/`show-slots` 复选框）的推广——每个路由声明自己的一组状态选项，切换器统一渲染在 `proto-bar` 区域，而不是像 v1 那样把状态开关硬编码在页面各处。
- 全局 `proto-bar` 保留并扩充：主题、协作规模模拟（新增，见 G-23）、reduced-motion/forced-colors 模拟（新增，见 G-25）、贡献槽位高亮，这些是跨路由生效的演示能力，不属于任何单一路由的状态。

### 5.2 v2"完成定义"（Definition of Done）

v2 原型交付时，以下 9 条流程必须**可点击走通**（允许边界情况仍标注"仅提示"，但主干路径不得是"静态"或"不可达"）：

| F5 离线与重连 | 六态状态机全部可切换查看（含 `connecting` 骨架，本轮新增） |
| F6 导出 | 格式/范围选择 → 生成中 → 完成，及至少 1 种失败态 |

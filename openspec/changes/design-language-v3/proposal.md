# Proposal

级别：L2
依赖：dev-process

## Why

用户 2026-10-04 指出现设计「整体有点奇怪」，以 Figma Slides 为优秀基准。对照截图与 playground token 后的差距：常驻的 Office ribbon 与右侧属性面板重复入口，顶部叠 4 层、底部 2 层，画布只占应用区约 1/3；藏青底、径向光晕、24px 毛玻璃、悬浮圆角卡与药丸按钮让颜色和形状泛滥；缩略图与模板是骨架条，不像真实产品。

## What Changes

- **BREAKING（界面结构）**：编辑器去掉 ribbon，改为 Figma 式结构——底部浮动工具条只管创建，右侧检查器只管当前选中对象的属性（随选中变化），其余命令进菜单、右键、⌘K 与快捷键；状态栏取消，同步状态、在线人数、插件异常分别并入文件名旁、头像组与按需横幅。
- 视觉改为中性平面：灰阶分层级，品牌蓝只做强调；面板贴边、1px 分隔；圆角 4–8px；紧凑控件；去掉渐变背景、光晕与毛玻璃；只有浮层带阴影。
- 缩略图、模板、最近文档改为真实渲染。
- 首页去掉问候大标题与「指南与帮助」卡片区，改为模板行 + 最近文档网格。
- 先做样张（`#/v3/home`、`#/v3/editor` 四种状态 × 亮暗，附两个备选强调色），过设计质量门、用户拍板后，再回写各线文档并把 playground 32 个界面全量迁移。
- 第 2 批（协作族）除界面外还改服务端接口与数据：分享链接令牌可重取与改链接角色、访问申请（端点、表与 Webhook 事件）、非所有者只读成员列表、命名版本校验与「恢复前」版本标记（rulings §4.25 DS-47、DS-48、DS-57、DS-67）。
- 第 3 批（应用壳族：开始页、文档列表、模板库、账户菜单、导入、导出、放映、查看器、嵌入、偏好设置、快捷键、命令面板、登录与错误页、管理页）新建界面规格 03-33（登录、会话与错误页），并改服务端接口与数据：导出作业取消端点（DS-101）、文档摘要的最近编辑者与按内容更新时间排序（DS-83、TB-144）、管理页插件行 `lastErrorPhase`（TB-119）、`GET /auth/config` 的 `trashDays`（TB-141）、`PATCH /users/me/profile` 删去 `avatarUrl`（TB-142）、`auth.selfSignup` 与 `auth.signupUrl` 的启动交叉断言（TB-143）、`auth.ok` 在元素上限时带两个数（TB-146）、RuntimeConfig `limits.importMaxBytes` 与 `templates.sources`（TB-147、TB-160）、停用账号重新登录带 `prompt=login`（DS-124）。
- 母版视图改版（2026-10-23 用户反馈「切换是切换不过去的」后选择按标杆重做，未采用推荐）：第一步把母版视图接成编辑器宿主的全局模式，第二步按 PowerPoint 幻灯片母版、Google Slides「编辑主题」、Keynote「编辑幻灯片版式」重画——画布列顶部一条上下文条写清在编辑什么、影响多少页与唯一出口，窗格选中即编辑对象（取消「版式 | 母版」范围单选），普通视图检查器加「编辑版式」入口，占位符与普通视图同一画法；只改界面，不改服务端（rulings §4.25 DS-144…DS-172）。
